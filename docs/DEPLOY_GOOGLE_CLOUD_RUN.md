Unauthenticated requests return 403. Revision `pets-model-00002-ms9` is ready and uses `gemini-3.5-flash-lite` with `pets-model-runtime@mdi-yimingwu-pets.iam.gserviceaccount.com`. Minimum instances are zero, the service and revision maximums are one, and concurrency is one. The runtime account does not yet have Vertex prediction permission. IAP access for selected people is not configured, and GitHub pushes do not automatically redeploy the service yet.

Cloud Run will host the chat page and its same-origin `/api/chat` endpoint. The server calls the project-scoped Vertex AI Gemini API using its [Cloud Run service identity](https://docs.cloud.google.com/run/docs/securing/service-identity). This route does **not** require a Gemini API key in ChatGPT, Codex, GitHub, the repository, or Cloud Run environment variables. A Google Cloud API key is not a console login; sign in to [Google Cloud Console](https://console.cloud.google.com/) with the Google account that has project access.

The project has billing and the Cloud Run, Cloud Build, Artifact Registry, and Vertex AI APIs enabled. A direct CLI request using the deployer's user credentials succeeded with `gemini-3.5-flash-lite`. The first revision used `gemini-2.5-flash`, which Google retired on October 20, 2026; the second revision uses the replacement. The direct test does not establish that the Cloud Run runtime can call Gemini.

## Remaining access and deployment work

- A project Owner grants the dedicated runtime account a custom project role containing `aiplatform.endpoints.predict`. This can be a copy of the narrow role used in `mdi-governance`. The account has no project role today. Do not replace it with the default Compute Engine account, which currently has broad Editor rights.
- An administrator with Cloud Run Admin and IAP Policy Admin access enables the IAP API and [IAP directly on the `pets-model` Cloud Run service](https://docs.cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run). In Cloud Run, open **pets-model → Security → Require authentication → Identity-Aware Proxy (IAP)**. Then use **IAP → Edit policy** to grant `roles/iap.httpsResourceAccessor` only to the invited Georgetown email addresses or Google Group. The IAP service agent needs Cloud Run Invoker; enabling IAP in the console grants that automatically. Do not disable the Invoker IAM check or grant access to `allUsers`. Users outside the Georgetown organization may require additional OAuth setup.
- A project Owner or billing administrator agrees on a small project budget and alerts before inviting users. Budget alerts are not hard spending caps.
- Connect `kathigg/pets_model` `main` to Cloud Build for automatic deployment only after the runtime access, cost limits, and private trial are agreed. Assign the build account the [required Cloud Run Builder permissions](https://docs.cloud.google.com/run/docs/deploying-source-code). Do not put a Gemini key in GitHub or Cloud Run.
- After runtime permission is granted, make one small hypothetical PET question through the Cloud Run service and verify that the answer uses Gemini and cites public sources. The browser fallback alone is not evidence that the model works.

The service already has `VERTEX_PROJECT_ID=mdi-yimingwu-pets`, `VERTEX_LOCATION=global`, and `GEMINI_MODEL=gemini-3.5-flash-lite`. Do **not** set `GEMINI_API_KEY` or `GOOGLE_APPLICATION_CREDENTIALS`. Keep minimum instances at zero, the service-level maximum at one, and concurrency at one. These settings reduce idle use and overlapping requests but do not cap model charges. [Service identity](https://docs.cloud.google.com/run/docs/securing/service-identity), [scaling settings](https://docs.cloud.google.com/run/docs/configuring/max-instances).

For automatic deployment, use **Cloud Run → Connect repository → Cloud Build**, connect `kathigg/pets_model`, select `main`, and use the repository-root `Dockerfile`. Each push to `main` then triggers a build and revision. The [repository deployment guide](https://docs.cloud.google.com/run/docs/continuous-deployment) lists the remaining build-account permissions. Check build history and service logs after each deployment.

## Cost and privacy

[Cloud Run has a free allowance](https://cloud.google.com/run/pricing), but usage beyond it can cost money. [Vertex AI Gemini use has separate pricing](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing). Direct IAP on Cloud Run avoids an added load balancer; [standard IAP protection has no added charge](https://cloud.google.com/iap/pricing). The app limits valid chat requests to 30 per 10 minutes across all visitors **per process**, and paid model calls to 20 per UTC day **per process**. Those counters reset on restart and are duplicated if instances or revisions overlap. Cloud Run can briefly exceed a maximum-instance setting. These safeguards are **not a hard dollar cap**. Agree on a low project budget and alerts with the grant owner before inviting users. Billing reports can lag; monitor them during the trial.

The app retrieves only original summaries of public PET sources. When Gemini is active, chat text and case details pass through Cloud Run to Vertex AI. Ask visitors to use hypothetical details, not protected student records or confidential partner information. See [the privacy boundary](../README.md#privacy-boundary) and [content policy](CONTENT_POLICY.md).
